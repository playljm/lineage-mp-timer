## 1. Root cause 5종 (우선순위 순)

### P0. mpBarRegion sourceId stale → captureStream 죽음 ⭐⭐⭐
**증상**: MP `???` 영원, anchor 8/8 굳음
**원인**:
- `regions.mpBar.sourceId = "screen:0:0"` (이전 세션 또는 모니터 토폴로지 변경 잔여)
- `captureRegionToCanvas` (app.js:2287)가 `captureStreams.get(region.sourceId)`로 캡처 스트림 조회 → cap 없음 → throw "캡처 스트림이 없습니다"
- v1.4.0+에서 도입된 ADENA 자동 stale 해제(app.js:4866~4871)는 **`_adenaManualOverride` 케이스만** 처리, **mpBarRegion에는 동일 보호 없음**
- 한 번 mpBar 캡처가 throw 되면 MP gauge 검증 회로가 fall-through하면서 mp 텍스트 OCR도 가중치 낮춰서 영원 폐기

**증거**:
- app.js:2289 `throw new Error('해당 영역의 캡처 스트림이 없습니다. (sourceId: ' + region.sourceId + ')')`
- app.js:2973 calibrateMpBarMax도 동일 경로
- app.js:1839~1851 setupCaptureStreams는 sourceIds Set에서 사용 중인 sourceId만 stream 생성 → mpBar의 stale sourceId 끊긴 채로 그대로

### P1. ADENA per-digit override가 anchor를 stale 값으로 굳힘
**증상**: OCR 25399 정확하지만 표시값 25,297
**원인**:
- `template 96097 vs OCR 25399` → template anchor가 96097로 stale
- v1.3.13 `_matchRecover` 패턴(app.js:4177)은 "anchor 자릿수 > OCR 자릿수 + 2회 연속 일치" 조건으로 자동 복구
- 하지만 96097(5자리) vs 25399(5자리) 자릿수 같음 → 복구 트리거 안 함
- per-digit voting에서 마지막 자리만 9→7 (anchor "97" 우측 영향) → adAdenaLast 25,297 출력
- 같은 5자리 "값 자체가 다른" stale anchor 케이스 미처리

**증거**:
- hybridLog: `🔧 ADENA per-digit override: 25295 → 25297 ([B-noisy] pos4:5→7 (v=4/10,tie, t=81%/gap=7%,NOISY))`
- p4 NOISY (template 자체 신뢰도 81%, gap 7%) 인데도 override가 OCR 5를 7로 변형

### P2. EXP textROI<50 sanity가 자동 모드에서 매 사이클 도배
**증상**: hybridLog 5회 중 4회가 "EXP textROI 폭 너무 좁음 (45px<50)"
**원인**:
- v1.5.1에서 `validateROIs`에 `rois.exp.width < 50` invalid 추가 (roi-detector.js:672~674)
- 자동 모드 ensureAutoModeROIs는 매 OCR 틱마다 호출되어 RoiDetector 재실행 (cachedROIs TTL 300s 미만이어도 fail counter 증가 시 재탐지)
- 사용자 게임창 사이즈에서 일부 사이클 expBar 후보 width 90px 부근 → expW_bar = expBar.width × 0.55 ≈ 49px → 50 미만 → invalid → 재탐지 → 같은 후보 → 같은 invalid 반복
- v1.4.2에서 도입한 throttle(30s, ensureAutoModeROIs._lastFailMsg)은 issues 텍스트 동일성 기반 — 한 글자라도 다르면 throttle 우회

**증거**:
- roi-detector.js:486 `expW_bar = Math.round(expBar.width * 0.55)` — 90×0.55=49.5 → 50px
- app.js:4728~4731 throttle 키 = `ensureAutoModeROIs._lastFailMsg.text` (issues 그대로)
- 같은 issue가 반복되어도 30s buffer만 지켜야 하는데 사이클 사이 다른 issue 끼면 reset

### P3. ADENA ROI 폭 부족 안내 — autoDetect.active=false에도 노출
**증상**: hybridLog "ADENA ROI 폭 부족" 3회 노출, 사용자 자동 모드 OFF 상태
**원인**:
- 진단 시 `autoDetect.active: false` (트래커 일시 정지) — 하지만 autoDetect.mode='auto' 라 ensureAutoModeROIs 자체는 계속 호출
- v1.4.2 throttle(30s)은 작동 중인데 다른 fail 메시지("EXP textROI 폭 너무 좁음")와 alternate 되어 30s 윈도우가 reset
- autoDetect.active=false 시점엔 OCR 사이클 자체를 멈추는 게 정합

### P4. displayCheck가 mpBar를 검증 대상에서 빠뜨림
**증상**: 진단 리포트 displayCheck.status=ok 인데 실제 mpBar sourceId mismatch 존재
**원인**:
- app.js:6004 `_diagRegions = { mp, exp, level, adena }` — **mpBar 누락**
- v1.3.21 displayCheck 도입 시 mpBar는 메인 텍스트 OCR 영역이 아니라 보조 게이지 측정용이라 빠뜨림
- 결과: P0 root cause를 진단 리포트가 자체 진단 못함 → 사용자가 알 방법 없음

## 2. v1.5.2 fix 5종 (코드 변경 위치 + 변경 내용)

### Fix #1 — mpBarRegion stale sourceId 자동 해제 (P0 해결)

**파일**: `src/js/app.js`
**위치**: line 4866~4871 ADENA stale 해제 블록 직후 (line 4871 이후)
**변경**:
```js
// [v1.5.2 fix] mpBar/level/exp/adena region이 gameRegion과 다른 sourceId면 stale로 간주 + 자동 해제
//   사용자 진단 (2026-05-08T12-21-25): regions.mpBar.sourceId = screen:0:0 stale,
//   gameRegion = screen:1:0 → captureStream 없어 captureRegionToCanvas throw 무한 발생 → MP "???"
//   ADENA-only 보호(line 4867)를 모든 OCR region으로 확장.
const _allRegionKeys = ['mpBarRegion', 'mpRegion', 'expRegion', 'levelRegion', 'adenaRegion'];
for (const key of _allRegionKeys) {
  const r = autoDetect[key];
  if (r && r.sourceId && r.sourceId !== gr.sourceId) {
    pushHybridLog('🤖 ' + key + ' stale sourceId(' + r.sourceId + ') vs gameRegion(' + gr.sourceId + ') — 자동 무효화');
    autoDetect[key] = null;
  }
}
```

**검증**: 사용자 진단 mpBar.sourceId screen:0:0 → null 자동 무효화 → 다음 ensureAutoModeROIs 사이클에서 textROIs.mp 재할당 → MP OCR 정상 복구

### Fix #2 — ADENA template anchor stale 자동 복구 (P1 해결)

**파일**: `src/js/app.js`
**위치**: line 4170~4188 `_matchRecover` 블록 (자릿수 같은 케이스 추가)
**변경**:
```js
// [v1.5.2 fix] anchor 자릿수 = OCR 자릿수 + 2회 연속 일치 + 큰 차이 — 추가 복구 케이스
//   사용자 진단 (2026-05-08T12-21-25): anchor 96097(5) vs OCR 25399(5) 자릿수 같음
//   기존 _matchRecover는 자릿수 다를 때만 트리거 → 같은 자릿수 stale 케이스 미처리
const valDigSame = anchorDig === valDig;
const bigDiff = Math.abs(anchorAd - valBoth) > anchorAd * 0.5;
if (valDigSame && bigDiff && valDig >= 4) {
  if (!ocrAdenaRegionHybrid._matchRecoverSameDig) ocrAdenaRegionHybrid._matchRecoverSameDig = { lastVal: 0, count: 0 };
  const mr2 = ocrAdenaRegionHybrid._matchRecoverSameDig;
  if (mr2.lastVal === valBoth) mr2.count++;
  else { mr2.lastVal = valBoth; mr2.count = 1; }
  if (mr2.count >= 3) {
    pushHybridLog('🔓 ADENA anchor 자동 복구 (paddle/tess 일치 + 큰 차이 50%+, 3회 연속): ' + anchorAd.toLocaleString() + ' → ' + valBoth.toLocaleString());
    mr2.count = 0; mr2.lastVal = 0;
    return voteHybrid('ADENA', pr, tr, (a, b) => a.adena === b.adena);
  }
  pushHybridLog('ADENA ⏳ anchor 복구 검증 (' + (mr2.count + 1) + '/3, 같은 자릿수 큰 차이) ' + valBoth.toLocaleString() + ' (anchor=' + anchorAd.toLocaleString() + ')');
  return { text: 'verifying ' + valBoth, confidence: 0, parsed: null };
}
```

**보완**: per-digit override 차단 — `_matchRecoverSameDig.count > 0` 동안엔 NOISY position override 적용 안 함 (검증 끝날 때까지)

### Fix #3 — EXP textROI<50 throttle 강화 (P2 해결)
