### Fix #4 회귀의 정확한 메커니즘

```bash
$ grep -nE '\.active\s*=' src/js/app.js
# tracker.active (15곳), trainLabeling.active (2곳)
# autoDetect.active = ... ← 0건!
```

`autoDetect.active`는 정의되지 않은 변수. v1.5.2 Fix #4의 게이트:

```js
if (!autoDetect.active && !opts.force) {
  // active=undefined → !undefined=true → 항상 진입
  // cachedROIs 없으면 false 반환 → ensureAutoModeROIs 본체 영영 안 돎
}
```

v1.5.2에서 OCR이 도는 것처럼 보인 건:
- 이전 v1.5.1 세션의 cachedROIs가 localStorage에 저장됨
- 새 v1.5.2 세션 진입 시 cachedROIs 그대로 → 첫 OCR 사이클은 운 좋게 통과
- 단, 새 ROI 탐지 0회 → mpBarRegion stale 영영 정리 못 됨
- 사용자가 재탐지 버튼/5회 fail invalidation 시 → 영영 막힘 → MP `???` 잠김

### Fix #1이 도달 못한 메커니즘

코드 위치 (v1.5.2):
```
ensureAutoModeROIs() {
  if (cacheHit) {
    textROIs = cached.textROIs;
    return ...;  // ← 여기서 종료
  }
  // 새 탐지 → toAbsRegion → Fix #1 (mpBarRegion stale 검사)  ← 이 경로만 거침
}
```

cacheHit 분기는 toAbsRegion 안 거침 → Fix #1 안 거침 → mpBarRegion 평생 정리 안 됨.

## 1. 진짜 root cause (v1.5.3에서 해결할 부분)

### R1. v1.5.2 Fix #4 즉시 revert
**위치**: `src/js/app.js:4651` ensureAutoModeROIs 진입부
**변경**: `autoDetect.active` 게이트 제거. PAUSE 노이즈 차단은 setInterval 시작/중지로 이미 처리됨 (line 5539).

### R2. mpBarRegion stale 검사를 진입부로 이동
**위치**: `src/js/app.js:4651` ensureAutoModeROIs 함수 진입부 (gameRegion 검증 직후)
**변경**: cacheHit/miss 모든 경로에서 1회 검사. v1.5.2의 toAbsRegion 직후 검사는 no-op으로 변경 (또는 제거).

### R4. 창 크기 모니터 클램프 강화
**위치**: `electron/main.js`
**변경**:
- `isWithinDisplay(x, y, w, h)` 창 전체 검증 (이전: x, y만)
- 신규 `clampToNearestDisplay(x, y, w, h)` — 가장 가까운 모니터 workArea로 강제
- default 1280x900 → 1100x820 (보수적)
- createMainWindow + ready-to-show 모두 클램프 적용

### R3. LEVEL voting 정책 (v1.5.4로 이동)
**보류 사유**: voting 정책 변경은 회귀 위험이 더 큼. 단독 PR로 분리하여 신중히 검증.
- 현재 증상: paddle=29 vs tess=23 (3/3 일관) → tess 우세 채택 → LEVEL=23 굳음
- 후보 1: 시작값 단계에선 양쪽 일치만 채택 (보수적)
- 후보 2: paddle 우선 (LV.29 글자 적은 편이라 paddle 정확)
- 후보 3: 기존 v1.4.3 Phase 5 LEVEL anchor 자동 복구 임계 완화 (7회→5회)
