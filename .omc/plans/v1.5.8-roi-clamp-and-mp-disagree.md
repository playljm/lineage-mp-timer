> **트리거**: 사용자 진단 `2026-05-08T14-05-41` (v1.5.7)

> 1. **Adena 22,974 → 2,274** misread (자릿수 누락)
> 2. **MP 177/242** Paddle 정확 / Tesseract `2/242` misread → DISAGREE 정책으로 매번 폐기
> 3. **EXP 49.99% → 41.60%** 큰 감소 (사망 추정) — UI 알림 없음

## 🔍 Root Cause 심층 분석

### Issue #1 — Adena ROI 우측 클램프 (가장 심각)

**진단 데이터**:
```json
"cachedROIs.anchors.adenaIcon": { x:1219, y:855, w:41, h:32 }
"cachedROIs.textROIs.adena":    { x:1214, y:882, w:64, h:22 }
"frameSize": { w:1278, h:958 }
```

**계산 추적** (`roi-detector.js:630~648`):
```js
rightCand.x     = 1219 + 41 + 3 = 1263
rightCand.width = max(90, 41 * 2.5) = 103     // 의도한 폭
// → x+width = 1366  (frameW=1278 보다 88px 초과)
```

**클램프 (`roi-detector.js:661`)**:
```js
if (r.x + r.width > frameW) r.width = frameW - r.x;
// width: 103 → 64  ← "22,974"가 "227 →2,274" 로 잘려 인식
```

그런데 **저장된 textROIs.adena 는 below 후보**(`x=1214, y=882`)임:
- belowCand.x = max(0, 1219-5) = 1214 ✅ 일치
- belowCand.y = round(855 + 32*0.85) = 882 ✅ 일치
- belowCand.width = max(50, 41*1.8) = 74 — 그러나 저장값은 64
- 즉 below도 frameW 1278 - x 1214 = 64로 클램프 (74→64, 10px 잘림)

**핵심 결론**: rightCand/belowCand 둘 다 **frame 우측 경계에 걸려서 잘림**.
사용자의 gameRegion(width=1278)이 Adena 영역을 다 못 담는 게 직접 원인.

**기존 가드의 허점** (`roi-detector.js:693`):
```js
if (name === 'adena' && r.width < 50) {  // 64 ≥ 50 이므로 통과 ❌
  adenaOnlyIssues.push(...);
  return false;
}
```
50px 임계값은 4자리 ADENA 기준. **5자리+콤마(22,974) 기준으로는 80~90px 필요.**

### Issue #2 — MP DISAGREE 영원 폐기

**진단 데이터**:
```
hybridLog: MP ❌ DISAGREE p={cur:177, max:242} t={cur:2, max:242, agreementCount:3, totalAttempts:5}
adMpLast:  ❌ "mismatch p:p：177/242"
```

**Paddle**: 정확하게 177/242 인식 (1회 시도, 단일 결과)
**Tesseract**: cur=2 (5회 중 3회 같은 misread — 일관된 오인식)

**현재 정책** (`app.js:4037~4040`):
```js
// 둘 다 성공 + 불일치 → 거부 (anchor 보존)
return { text: 'mismatch ...', confidence: 0, parsed: null };
```

**문제**: Tesseract가 일관되게 misread 하면 **DISAGREE 무한 발생** → MP "???"  영원.
v1.5.5 D fix 가 LEVEL 에 paddle 우선 도입했고, A++ MP anchor stale 양방향 도입했지만,
**MP cur 의 paddle-우선 채택 정책은 아직 없음**.

## 🎯 작업 범위 (v1.5.8)

### HIGH-1 — Adena ROI 우측 클램프 명시 감지
**파일**: `src/js/roi-detector.js`

1. `deriveTextROIs` 클램프 직전에 **원래 의도한 width 보존**:
   ```js
   const intendedWidth = r.width;
   if (r.x + r.width > frameW) r.width = frameW - r.x;
   r._clipped = (r.width < intendedWidth);
   r._intendedWidth = intendedWidth;
   ```

2. `validateROIs` adena 분기 강화:
   - 임계값 `< 50` → **`< 80`** (5자리+콤마 보장)
   - `_clipped` 플래그 있으면 **frame 경계 초과 명시 메시지**:
     `"ADENA ROI 우측 클램프 (의도 ${intended}px → ${width}px) — 게임 영역을 우측으로 ${intended-width+10}px 이상 확장"`

3. `belowCand` 도 동일 클램프 감지 적용 (현재는 below도 잘리고 있음).

### HIGH-2 — MP DISAGREE 시 Paddle 우선 채택 휴리스틱
**파일**: `src/js/app.js` `voteHybrid` (line 4019~)

**채택 조건 (모두 만족)**:
1. `label === 'MP'`
2. paddle.parsed.max === tess.parsed.max  (max 일치)
3. paddle.parsed.cur 는 합리적 (`cur ≥ 1` 그리고 `cur ≤ max`)
4. tess.parsed.cur 가 비정상적 — 둘 중 하나:
   - `tess.cur < paddle.cur * 0.2` (Paddle의 20% 미만 = 자릿수 손실 의심)
   - `tess.cur < 10` AND `paddle.cur ≥ 50` (한자릿수 vs 두자릿수+ 격차)
5. `userMax` 가 paddle.max 와 일치 (anchor sanity)

**채택 시**: `pushHybridLog('MP ⚖️ paddle 우선 채택 (tess 자릿수 손실 의심) ...')` + paddleR 반환.
**미채택 시**: 기존 disagree 거부 유지.

**범위 제한**: MP 한정. EXP/ADENA 는 별도 검증 메커니즘이 이미 있음 (큰 점프, 자릿수 anchor 복구).

### MED-1 — EXP 큰 감소 토스트 알림
**파일**: `src/js/app.js`

EXP 점프 검증 통과 시점(`expBigJumpVerified` 또는 동등 위치)에:
- `delta < -5` (감소) → `flashHint('⚠️ EXP -' + Math.abs(delta).toFixed(2) + '%p — 사망 또는 트래커 리셋?')`
- 옵션: `localStorage.lmp.expDeathToast` (기본 ON)
