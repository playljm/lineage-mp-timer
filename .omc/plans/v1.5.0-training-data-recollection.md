## 0. 컨텍스트 — 왜 P2가 필요한가

### v1.4.3까지 적용된 모든 휴리스틱
| 영역 | Fix |
|---|---|
| Capture | gameRegion ROI 자동 detect, frameW 클램프, 다른 모니터 검증 |
| OCR Engine | paddle + tesseract hybrid, 4 캔버스 ensemble × 3 PSM |
| Preprocessing | white-extraction T=140/110/luminance dual, autoTrim, chromaMask |
| Voting | hybrid 일치, paddle/tess 단독 채택 (anchor sanity), per-digit voting (ADENA) |
| Validation | 자릿수 sanity, ±20 plausibility, 큰 점프 N회 검증, anchor 자동 복구 |
| Stability | 디폴트 3, confusion-aware +1 (0↔8/5↔8/6↔8/4↔9/7↔1/9↔7) |

### 그래도 새는 케이스 (paddle/tess 본질적 한계)
- paddle: 픽셀 폰트 학습 부족, 0/8/5/6 confusion
- tess: 우측 빈 영역에 노이즈 합치는 경향, 슬래시 무시
- 두 엔진 모두 같은 misread (예: 둘 다 8→5)
- LEVEL ROI 같은 작은 영역에서 일시 텍스트 misread

### 이전 학습 시도 (2026-05-03) 실패 원인
| 항목 | 값 |
|---|---|
| 라벨 수 | 463개 |
| BCER (학습) | 4.02% → 1.96% (2배 개선) |
| 실전 결과 | **오히려 인식 더 악화** ❌ (오버피팅) |
| 원인 | 데이터 편향 — LEVEL 41/42=`28`, MP 90%=`/235`, EXP 27~32% 좁은 구간 |
| 조치 | `eng+lineage` → `eng` 단독 복구 (`91bb29d`) |

**핵심 교훈**: 데이터 양보다 **다양성**이 결정적.

## 2. 데이터 수집 전략

### 2.1 자연 사냥 캡처 (낮은 비용, 다양성 자동)

```
사용자가 평소대로 사냥 → 앱이 자동으로 PNG + OCR 추천값 저장
경로: %APPDATA%\LineageMPTimer\training-data\{mp,exp,level,adena}\
파일 형식: <timestamp>.png + <timestamp>.gt.txt (라벨)
```

**자동 캡처 시스템 이미 구현됨** (v1.2.0-paddle, 2026-05-03 commit). 사용자 액션 없이 데이터 누적.

### 2.2 다양성 보강 (의도적 캡처)

| 영역 | 다양성 기준 | 캡처 방법 |
|---|---|---|
| LEVEL | Lv.1, 5, 10, 15, 20, 25, 29, 30, 40, 50, 60, 70, 80, 99 | 다른 캐릭 또는 부캐 |
| MP cur | 0~max 골고루 (10단위) | 사냥/마법 사용 다양한 시점 |
| MP max | 100, 150, 197, 200, 242, 300, 400, 500 | 다른 캐릭 |
| EXP | 0%, 5%, 15%, 30%, 50%, 75%, 99% | 시간 두고 계속 사냥 |
| ADENA | 3자리(100~999), 4자리, 5자리, 6자리, 7자리, 8자리 | NPC 거래로 변동 |

### 2.3 어려운 케이스 우선 (confusion pair 학습)

CLAUDE.md `OCR-FUTURE-PLAN.md` 우선순위:
- **0↔8** (slashed zero) — 80, 808, 8080, 80808 등
- **5↔8** — 5/8 동시 등장 (158, 585, 858 등)
- **6↔8** — 6/8 동시 등장
- **4↔9** — 49, 94 등
- **7↔1** — 71, 17 등
- **3↔4** (ADENA template)

각 confusion pair 글자 50~100개 다양하게 caught.

## 3. 라벨링 단계

### 3.1 앱 내 라벨링 패널 사용

```
앱 → 설정 → "사후 라벨링" 패널
→ 자동 캡처된 PNG 목록 표시
→ OCR 추천값 미리 채워짐
→ 사용자가 정확한 값 확인/수정 후 Enter 연타로 정리
```

**시간 비용**: 1000개 라벨링 ~ 2~3시간 (Enter 연타 + 가끔 수정)

### 3.2 품질 관리

- 잘못 라벨링 시 학습 모델 깨짐 → 재학습 시 더 악화
- 5/6/8/0 confusion pair 글자는 **2번씩 검증** (다른 시간에 다시 보기)
- 모호한 캡처(흐릿, 잘림)는 **삭제**

## 4. 학습 단계 (WSL Ubuntu + tesstrain)

### 4.1 환경 (이미 보존됨)

```
WSL 배포판:        Ubuntu (root)
워크스페이스:       /root/tesstrain/
Ground truth:     /root/tesstrain/data/lineage-ground-truth/
체크포인트:        /root/tesstrain/data/lineage/checkpoints/
베이스 모델:       /root/tesstrain/tessdata_best/eng.traineddata
출력:            /root/tesstrain/data/lineage.traineddata
```

### 4.2 명령

```bash
# 1. 데이터 동기화 (Windows training-data → WSL ground-truth)
wsl.exe -d Ubuntu -u root -- bash //root/setup_data.sh

# 2. 추가 학습 (체크포인트에서 이어 학습)
wsl.exe -d Ubuntu -u root -- bash -c "cd /root/tesstrain && \
  make training MODEL_NAME=lineage START_MODEL=eng \
  TESSDATA=/root/tesstrain/tessdata_best \
  MAX_ITERATIONS=20000 PSM=7"

# 3. 결과 검증 (학습 vs 검증 BCER 분리)
# 검증 데이터는 학습에서 제외하고 별도 분리

# 4. 빌드 통합
wsl.exe -d Ubuntu -u root -- cp /root/tesstrain/data/lineage.traineddata \
  /mnt/c/dev/lineage-mp-timer/build/tessdata/

# 5. 앱 재빌드
cd /c/dev/lineage-mp-timer && npm run build
```

### 4.3 메트릭 추적

- **BCER (학습)**: <1% 목표
- **BCER (검증)**: <2% 목표 (학습보다 약간 높음 정상)
- **차이 (overfitting 측정)**: 학습 BCER - 검증 BCER < 0.5% 권장

## 5. 검증 단계 (실전 적용 전)

### 5.1 A/B 테스트 빌드

이전 학습 실패 교훈: 학습 BCER 좋아도 실전 다를 수 있음.

```
빌드 A: 현재 (eng 단독)
빌드 B: 신규 (eng+lineage)
```

같은 사용자 진단 캡처 10~20장으로 A/B 비교:
- A 인식률 vs B 인식률
- B가 명백히 좋으면 통합. 그렇지 않으면 추가 데이터 + 재학습.

### 5.2 사용자 다중 캐릭 검증

여러 캐릭 환경에서 1주일간 자동 캡처 + 사용자 평가:
- "이전보다 인식 잘 되나?" — 사용자 직접 평가
- "어떤 영역에서 잘 안 되나?" — 추가 데이터 수집 우선순위

## 8. 즉시 액션 vs 장기 액션

### 8.1 즉시 (이번 진단 LEVEL "5" 문제 해결)

```
1. 트래커 LEVEL NOW 칸 클릭 → "29" 직접 입력
2. 5초 OCR skip 후 자동 안정화
3. 사용자 환경에선 OCR 다수결 미달이라 anchor 갱신 안 되니
   미리 정확한 값 anchor로 굳히기
```

이건 **이번 세션 내 해결**.

### 8.2 단기 (1~2주 내)

```
1. 사용자 자연 사냥 — 자동 캡처 누적 (이미 활성화)
2. 1주 후 capture inventory 점검 → 어느 영역/값 부족한지 파악
3. 부족 영역 의도적 캡처 (다른 캐릭/시점)
```

### 8.3 중장기 (1~3주 내)

```
1. 1500+ 라벨 정리 → WSL 학습 → 검증 → A/B 빌드
2. 사용자 1주 평가 → 회귀 없으면 통합
3. v1.5.0 release
```
