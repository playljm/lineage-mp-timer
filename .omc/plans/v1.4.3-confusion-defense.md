## 1. 문제 본질

```
픽셀 폰트 글리프 (16~24px height):
  '0' = 둥근 사각, 가운데 빈 공간
  '8' = 둥근 사각, 가운데 가로획
  '5' = 위/아래 닫힌 곡선, 우측 열림
  '6' = 좌측 갈고리 + 닫힌 하단
```

OCR 모델 (paddle/tess)은 자연 이미지 학습 분포 → 픽셀 폰트의 미세 차이(가운데 1픽셀 가로획) 구분 약함.

### 이미 적용된 방어
| 방어 | 효과 |
|---|---|
| 4 캔버스 ensemble (pp/soft/otsu/raw) | 한 캔버스 misread를 다른 캔버스로 보정 |
| White-extraction T=140/110 | 어두운/베이지 글자 모두 처리 |
| Hybrid voting (paddle+tess) | 두 엔진 약점 다른 자리에서 만남 |
| Stability=2 | 2회 일관 시만 갱신 |
| Anchor sanity (자릿수, ±20) | 큰 점프 차단 |
| Per-digit voting (ADENA) | 자리별 다수결 |

### 그래도 새는 케이스
- paddle/tess 모두 같은 misread (예: 둘 다 8 → 5)
- 2회 연속 같은 misread (stability=2 통과)
- anchor가 misread 값으로 굳어 정상 결과가 거부

## 3. 해결 카드 (P0~P3)

### Card P0 — Stability 강화 (즉시, 안전)
**변경**: `autoDetect.stabilityRequired = 2 → 3` 디폴트 + 설정 UI

**적용 범위**: MP/EXP/Level/ADENA 동일

**효과**:
- 한 사이클 misread (1초)는 자동 흡수
- 두 사이클 일관 misread 일부도 흡수 (3회 요구)
- 정상 변화도 1초 지연 (의미 미미)

**리스크**:
- 정상 사냥 중 갱신 1~2초 지연
- 사용자가 빠른 갱신 원하면 설정 OFF 필요

**구현 비용**: ~10줄

### Card P1 — Confusion-aware Verification Queue
**조건**:
1. 새 OCR 결과가 anchor와 다름
2. 자릿수 동일
3. Levenshtein=1 (1자리 차이)
4. 차이 자리 글자가 confusion pair에 해당 (`{0,8}, {5,8}, {6,8}, {4,9}, {7,1}, {9,7}`)
→ 의심 misread → 3회 일관 통과 시만 갱신

**효과**:
- "1908 → 1508" (5↔8) 단발 misread → 자동 거부
- "242 → 248" (4↔8) 거부
- 진짜 글자 변화 (예: 1908 → 1909, 5 위치 글자 그대로) → 정상 갱신

**리스크**:
- confusion pair 해당이면 정상 변화도 검증 (1~3초 지연)

**구현 비용**: ~80줄 (MP/ADENA 별도)

### Card P2 — 학습 데이터 재수집 + traineddata 재학습
**프로세스**:
1. 사용자 게임 환경에서 1000~2000 라벨 수집 (자동 캡처 + 라벨링)
2. WSL traineddata 재학습 (`docs/TRAINING-PIPELINE.md`)
3. 새 모델 검증 → 인식률 95%+면 빌드 통합

**효과**:
- 5↔8, 0↔8 confusion 근본 해결
- hybrid voting 단순화 가능

**비용**: 1~2주 (수집 + 라벨링 + 학습 + 검증)

**리스크**:
- 이전 463개 학습은 오버피팅 (2026-05-03 실패)
- 데이터 다양성 확보 필수

### Card P3 — Paddle per-digit confidence 활용
**가설**: paddle이 글자별 confidence 출력 시 낮은 confidence 자리만 cross-check

**구현**:
1. paddle SDK 확인 (`@paddlejs-models/ocr`) — character-level confidence 제공 여부
2. 제공 시: 낮은 confidence 자리만 추가 ensemble
3. 미제공 시: P3 폐기 또는 다른 방향

**비용**: 조사 1~2일 + 구현 1주 (제공 시)
