## 🚨 남은 잔여 이슈 (v1.5.13 작업 예정)

### Issue A — ADENA "5" misread (CRITICAL)

**진단**: `2026-05-08T16-33-53`
```json
"anchors.adenaNow": "5"        // 이전 54891 → 5 갱신됨 (큰 손실)
"adAdenaLast": "✅ 5 ×10"      // 10회 일관 → anchor 굳음
이미지 (adena.png): "61865"     // 실제 값은 5자리
```

**root cause 추정**:
- v1.5.12 ADENA 다단계 white-extraction 추가 (T=140 RGB + T=120 lum + **T=70 lum**)
- `whiteDeep` (T=70 lum) — 너무 관대한 임계값 → 글자 일부만 추출 → 단일 자릿수("5") OCR 결과
- 다수결 voting 시 다양한 캔버스에서 "5" 가 여러 번 나오면 채택
- **위험**: 큰 점프 검증(54891→5)이 어떻게 통과했나? 10회 일관이면 영원 anchor 굳음

**fix 후보**:
1. **whiteDeep T=70 → T=85** (덜 관대하게) — 글자 끊김 방지
2. **자릿수 sanity**: ADENA OCR 결과 자릿수가 anchor 자릿수의 50% 미만이면 **catastrophic misread** 의심 → 폐기
   - 예: anchor=54891 (5자리) vs OCR="5" (1자리) → 4자리 차이 → 폐기
3. **다수결 voting 자릿수 가중치**: 짧은 자릿수에 패널티
4. v1.5.5 E fix 패턴 — anchor 자릿수 부족 자동 복구는 *있지만*, 반대 방향(OCR 자릿수 부족 → anchor 보호) 추가 필요

**우선순위**: P0 — 사용자 트래커가 이번 진단 시점에 anchor=5로 굳어있음.

### Issue B — Tesseract worker hang `+1108s` (HIGH)

**진단**: `2026-05-08T16-33-53`
```
adInitStatus: ⏳ recognizing text 0% (+1108s)
```

v1.5.12에서 30s recognize timeout 추가했지만 18분 hang. 가능 원인:

1. **`recognizing text 0%`는 init 단계 logger** — Tesseract.createWorker 진행률. recognize 호출이 아니라 worker 초기화가 0%에서 hang.
2. 그러면 v1.5.12 timeout은 recognize 호출에만 적용, **init은 별도 60s timeout 보호** 받지만 60초 후 throw 되어야 함.
3. 그런데 1108s 동안 0% — init 60s timeout 도 작동 안 했거나, 재초기화 → init → 60s timeout → 다시 init 무한 루프
4. 또는 logger 메시지만 stale, 실제 worker 는 다른 상태

**확인 필요**:
- Tesseract.js v7 + Electron 33.4 + lineage.traineddata 호환성
- 패키징된 환경(workerBlobURL: false)에서 worker 생성 자체가 hang하는지
- `adInitStatus` 메시지 갱신 로직 — 진짜 0%에서 멈춘 건지 stale UI 인지

**fix 후보**:
1. **Tesseract worker init도 30s 단축 timeout** + N회 재시도 후 fallback (paddle 단독 모드)
2. **Tesseract 비활성화 옵션**: 사용자가 paddle-only 모드 선택 가능 (UI 토글)
3. **recognize timeout 발생 시 ocrEngine을 임시로 paddle로 강제 전환** — Tesseract 복구 시도 N회 후
4. Tesseract.js v7 → v5 다운그레이드 검토 (CDN URL 보면 v5 였는데 package.json은 v7) — version mismatch 가능성

**우선순위**: P1 — 가끔 발생하지만 사용자 경험 영향 큼. 회피 가능 (재실행 시 초기화 정상).
