### 게임 스크린샷 분석 (결정적)

좌측 하단 미니 패널 구조:
```
글루디오 던전 5층
[캐릭]  LEV:29  [아바타]  39.6107%
        -40    🌙        15%
        28%    🪙       100%
        Lawful          32767
```

**이 게임 UI에는 EXP 진행 막대(progress bar)가 없음**. `LEV:29`와 `39.6107%` 모두 노란/오렌지 톤 텍스트로만 표시. 사이의 캐릭터 아바타로 인한 시각적 갭이 cluster 분리 단서.

진단 cachedROIs.anchors.expBar:
- `{x:1, y:773, width:85, height:26, avgHue:28.78, avgSat:0.78}`
- avgHue 28 + avgSat 0.78 = 노란-오렌지 톤
- 이는 **"LEV:29" 텍스트 글자 자체**를 expBar로 false-positive 채택한 것

deriveTextROIs `useExpand = expBar.height < 12` → 26<12 **false** → "막대 두꺼움" 분기 (line 557~)
- 단순 0.4/0.55 분할 → LEVEL ROI = LV:29 글자 좌측, EXP ROI = LV:29 글자 우측 ":29"
- `findLevelTextLines` 분기 우회 → 이게 root cause

### MP "131/242 → 3/8" 진짜 원인

진단 anchor `mpCur=3, mpMax=8` 굳음. 화면 실제 131/242:
- paddle "131/242" → max(242) ≠ userMax(8) → pBaseValid=false → 폐기
- tess catastrophic misread "3/8" → max(8) === userMax(8) → 통과 → adMpLast `✅ 3/8 ×3`

v1.4.2 mpMax 자동 복구 게이트:
```js
if (um >= 10 && pmx !== um && pmx >= 50 && pmx <= 9999 && ...)
```
사용자 mpMax=8이 `um >= 10` 게이트에 막혀 자동 복구 영영 안 됨.

## 1. v1.5.4 fix 3종

### A. MP cur+max 동시 stale 자동 복구 (`app.js:4081`)
**변경**: 게이트 `um >= 10` → `pmx >= um*2 || um === 0` (stale 의심 기준).
복구 시 `dom.inMaxMp.value` 외 `dom.inCurMp.value`도 paddle.cur로 갱신.
효과: mpMax=8 같은 작은 stale 값도 5회 paddle 일관 시 cur+max 동시 복구.

### B. 막대 두꺼움 분기에서도 findLevelTextLines 우선 (`roi-detector.js:557`)
**변경**: useExpand=false 분기에서도 `findLevelTextLines` 시도.
- 2개 이상 cluster + 두 cluster 사이 gap>20px 명확 분리 시 텍스트 라인 ROI 채택
- 실패 시 기존 단순 분할 fallback
효과: EXP 진행 막대 없는 UI에서도 텍스트 cluster로 LEVEL/EXP 분리.

### C. expBar 후보 aspect 기반 우선순위 (`roi-detector.js:findExpBarCandidates`)
**변경**: `aspect >= 5 && height <= 12` (얇은 가로 막대) 우선, 두꺼운 후보(텍스트 의심) 후순위.
완전 reject 아닌 ordering — false negative 위험 회피.
효과: 진짜 EXP 막대 있으면 우선 채택, 없으면 텍스트 후보로 fallback.
